# 演示验收路线

本路线使用独立的演示 SQLite 数据库，不使用真实 Google 凭据或付费模型。AI 回答、Google 搜索数值是模拟数据；站点抓取、体检、分析、行动和报告使用应用代码。页面与导出周报均标识演示来源。请勿把演示点击、接受行动或报告数字计入真实激活和增长。

## 启动

按 README 运行 `make demo`，中文题目可用 `make demo DEMO_LANG=zh`。使用 `demo` / `quillpad-demo-2026` 登录。生成器只接受不存在的新数据库路径，已有演示数据不会被自动覆盖。中、英、葡界面均可查看导览；目前预置 AI 回答夹具有中、英两种，葡语 UI 不会改写它们。

项目选择器中包含三个项目：

- `quillpad`：AI、抓取、体检和已接受行动。
- `quillpad-new-site`：90 天完整覆盖、低流量搜索，展示新站观察及稀疏样本边界。
- `quillpad-established`：90 天完整覆盖、最近 28 天点击下降，展示持续下降、独立查询/页面和国家/设备维度。

无需点击“同步 Google”或启动模型采样。切换项目后从总览的“五分钟演示导览”开始。五分钟是夹具体验目标，不是外站抓取 SLA 或真实用户 TTV 结论。

## 五步路线

1. **找到证据。** 在 AI/体检项目打开一个体检问题，读 URL、规则及修复条件。切换新站与完整历史站点，分别说明为什么“流量小”不等于异常、为什么完整历史可以提出持续下降待查。
2. **检查比较条件。** 打开搜索页面、查询、国家或设备列表，检查时间范围、覆盖、来源及独立粒度。筛选和下钻后再导出，确认范围一致。Google 点击与 GA 会话不是同一个分母；模拟题库的结果也不能当业务收益。
3. **接受一项有帮助的行动。** 阅读依据和验收条件后再接受；确认进入“进行中”。只有用户明确操作才写入首次价值记录，打开导览不自动记录。
4. **记录真实修改与观察窗口。** 在已接受行动中填写假设、实际修改时间、目标 URL/问题、主指标及护栏，再记录上线。基线冻结后，资料不足或窗口未成熟应保持待观察/证据不足；任务完成不等于效果改善。没有真实修改时，不应为了演示伪造上线记录。
5. **周复盘。** 生成或查看周报，核对已更新行动、到期观察和下周至多三项重点。切换报告语言应只改变报告，不改变题目或采样语言。Google 未连接时仍可复盘已有 AI/体检证据。

## 真实项目验收记录（未执行）

后续需陪同 5–10 个真实项目记录：开始配置时间、首次读懂证据时间、明确标记有帮助/接受行动时间、阻塞原因、是否一周后回来复盘。分别统计无 key、无 Google、不可达站点、部分抓取成功等状态。不要用自动化页面打开耗时代替用户首次价值耗时。

Google 实际资源的字段兼容性、历史回填、配额恢复与 MySQL 8 需在授权的真实环境单独验收。当前仓库测试使用 SQLite、HTTP 夹具和浏览器 mock；它们不证明外部服务已验收。
